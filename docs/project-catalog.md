# Project catalog and input contracts

This catalog describes the current code, including source-level settings and notebook cells, as inspected on November 3, 2026. The repository contains two main subsystems, `oscilloscope/` and `rf/redstone/`, with a closed-loop project nested under Redstone. Some projects are runnable scripts or notebooks; others are reusable Python modules.

## Shared data contracts

| Input | Representation and assumptions |
| --- | --- |
| Raw scope trace | `ScopeWaveform`: equal-length one-dimensional `time` and `voltage` arrays, seconds and volts, plus sample rate, source/channel, and preamble metadata. Analysis assumes a regularly sampled RF voltage trace. Calibration functions check finite values and strictly increasing time; this does not establish sampling adequacy or absence of clipping. |
| Measured-waveform CSV | BB1 loader requires `time_s` and a voltage column whose name ends in `voltage_v`, case-insensitively, such as `chan1_voltage_V`. It uses the first matching voltage column. Leading `#` metadata rows are allowed. At least three valid samples are required; sample rate is inferred from the median time spacing. This is not an arbitrary instrument CSV importer. |
| Demodulated trace | `DemodulatedWaveform`: time, I/Q voltage, complex envelope, amplitude, unwrapped phase, and demodulation metadata. Amplitude is peak-envelope voltage, not RMS voltage or dBm. |
| Intended amplitude CSV | Exactly one numeric column, finite and nonnegative, in Hz or kHz of Rabi frequency `Omega/(2*pi)`. A header can be skipped. Unit inference uses the filename/header, or an explicit unit setting. This is a plot overlay, not the raw RF input or a TNMR upload file. |
| Intended phase CSV | Exactly one finite numeric column in degrees or radians, inferred from the filename/header or selected explicitly. Phase is unwrapped. This is also a plot overlay. |
| Overlay time axis | The amplitude/phase comparison scripts stretch the supplied samples uniformly across the detected measured-pulse duration. There is no timestamp column or automatic delay/duration identification. Phase comparison fits one constant phase offset on sufficiently strong measured samples. |
| TPS file | Binary TNMR pulse-sequence file, loaded by `Sequence`. Edits depend on existing parameter names, table names, control-line names, and one-based event numbers. |
| TNT file | TNMR experiment/document container, opened through COM for software control. Certain notebooks edit an embedded sequence in a known matched TNT/TPS template pair; these are not general TNT reconstruction tools. |
| Waveform JSON | Configuration generated by `Waveform.write_json()`, identifying a registered waveform type and its parameters. This differs from a `Sequence` JSON dump and from calibration JSON. |
| Calibration JSON | Numeric calibration results plus units and acquisition metadata. The heatmap and closed-loop scripts currently use source-level calibration constants; they do not automatically ingest these JSON artifacts. |

The inherited scope defaults commonly use `TCPIP::192.168.1.152::INSTR`, CHAN1, demodulation frequency 601.0100113 MHz, and a 25 MHz baseband low-pass cutoff. These are lab settings, not device-independent truths. Q conventions differ: the two calibration CLIs default to `I+iQ`, while the heatmaps and closed-loop settings default to `I-iQ`. Consistency with the actual RF phase convention must be established.

## Oscilloscope projects

### O1. Time-window capture — `examples/capture_time_window.py`

- **Purpose:** arm a RIGOL DHO for a single trigger, optionally run a shot-start command after arming, wait for acquisition completion, read the selected time interval, and save a CSV. Multiple shots are supported.
- **Inputs:** scope IP or VISA resource, channel, `--t1`/`--t2`, shot count, timeouts, output path, and optionally `--shot-command`. Default time interval is -23.8 to 100 microseconds. Time arguments accept seconds or strings such as `-1us`.
- **Modes:** normal mode waits for a fresh triggered shot; `--read-current` reads the currently stored trace. Reading a stored trace does not mean loading an offline file.
- **Assumptions:** the external RF/trigger source and scope acquisition settings are already suitable; the time interval refers to the scope time axis and must be available in acquisition memory. There is no sequence-generation step in this script. The CLI requires explicit `--allow-clamp` to tolerate a requested window beyond available data.
- **Outputs:** a waveform CSV with seconds/volts and metadata. The writer chooses a numbered sibling if a requested output file already exists.

### O2. Interactive connection/capture — `examples/oscilloscope_connection_pipeline.ipynb`

- **Inputs:** `SCOPE_IP`, `VISA_RESOURCE`, a channel list, timeout, and capture bounds; defaults are CHAN1 and -10 to 30 microseconds.
- **Behavior:** connect and query identity, select RAW/ASCII waveform readout, read current waveform memory channel by channel, save CSVs under `captures/`, plot them, and close the connection.
- **Optional repeated shots:** the later cell uses `capture_single_waveform`; `REPEAT_SHOTS=0` disables that loop initially. It prompts the operator to start an external trigger source after the scope is armed.
- **Assumptions:** channels read in sequence are not a guarantee of a synchronized multichannel shot. The default read configurations allow clamping to the available window. This notebook contacts the scope when run.

### O3. Square-pulse amplitude calibration — `examples/calibrate_rf_from_square.py`

- **Inputs:** live/current scope trace of a TNMR amplitude-100 square RF pulse, known physical Rabi frequency at that setting, carrier frequency, low-pass cutoff, Q convention, and scope window. The suggested pulse is 10–20 microseconds; the capture window defaults to -10 to 80 microseconds.
- **Current physical reference:** `PEAK_OMEGA_OVER_2PI_KHZ=123.96840469314181`, overridable with `--peak-khz`. The script cannot infer the physical spin Rabi frequency from scope voltage alone.
- **Method:** smooth the envelope over 0.25 microseconds; detect the longest high-envelope interval at a 0.5 contrast threshold; remove out-of-pulse I/Q baselines with a 0.5 microsecond guard; take the median envelope in the central 60% of the pulse. It requires at least 20 usable out-of-pulse baseline samples.
- **Assumptions:** a sustained square pulse with a meaningful plateau, sufficient background, no clipping, and a valid independently known amplitude-100 reference. Conversion is `scale = 2*pi*f_Rabi / median_envelope_voltage`, in rad/s/V.
- **Outputs:** `rf_square_calibration.json`, diagnostic figure, plateau spread/MAD, and a printable `SQUARE_PULSE_OMEGA_RAD_S_PER_VOLT` assignment.
- **Input boundary:** the CLI has no raw CSV option. The pure `calibrate_square_waveform()` function accepts a `ScopeWaveform`, which another caller can construct from offline data.

### O4. BB1-area calibration — `examples/calibrate_rf_from_bb1.py`

- **Inputs:** a complete BB1 RF pulse, its intended target rotation angle, demodulation settings, and optionally manually selected pulse bounds and a known primitive pi/2 duration.
- **Input selection:** source-level `INPUT_CSV` defaults to `tests/pulse1_008.csv`; set it to another matching capture CSV for offline input, or to `None` for live/current-scope acquisition. There is no `--input-csv` flag.
- **Method:** baseline-correct I/Q using at least 20 out-of-pulse samples; integrate the corrected envelope; assume total transverse area `4*pi + theta`; compute `scale = (4*pi + theta) / integral(envelope dt)`. The default target is 90 degrees, giving 4.5*pi, not the 5*pi used for BB1 X(pi).
- **Assumptions:** the input really is a complete BB1 pulse with the assigned angle/area. Assigning this area does not independently verify that the pulse realizes the intended gate. A truncated pulse or a different waveform invalidates the premise.
- **Optional cross-check:** a supplied pi/2 duration gives `f_Rabi=1/(4*t_pi_over_2)`; a usable constant plateau permits comparison with the area-derived scale.
- **Outputs:** `rf_bb1_calibration.json`, rad/s/V and kHz/mV conversion factors, baseline/window metadata, cumulative-area diagnostics, and an optional duration cross-check.

### O5. Robustness relative to the measured nominal pulse — `examples/scope_rf_robustness_heatmap.py`

- **Inputs:** live/current raw RF trace; carrier, Q convention, acquisition window; pulse type; voltage calibration or BB1 target angle; optional intended-amplitude and intended-phase CSVs.
- **Pulse modes:** `complex` uses the fixed square-pulse calibration. `regular-bb1` rescales the measured envelope to `4*pi + theta`; its default target angle is 90 degrees.
- **Current defaults:** complex mode; -10 to 100 microseconds; 900 time steps; 101-by-101 grid; fractional amplitude error and normalized detuning both -0.5 to +0.5. The fixed scale currently equals 1776212.654495664 rad/s/V and must match the lab calibration.
- **Target:** the unitary produced by this same measured waveform at zero amplitude error and zero detuning. The center is unity by construction up to numerical error. A high value therefore means insensitivity relative to the nominal measured operation; it does not prove an ideal X(pi) gate.
- **Extra assumptions:** automatic windowing spans the first through last envelope sample above 10% of peak plus 0.25 microsecond padding, so multiple separated pulses can be merged into one window. The intended amplitude/phase CSVs are only uniformly timed comparison traces.
- **Current path dependency:** both overlay paths are enabled and point into `C:\Users\ctcheung\Downloads`. Replace them with actual files or set them to `None` before running on another computer.
- **Outputs:** fidelity heatmap, threshold-region summaries, optional pulse diagnostics and command/measurement overlays. There is no raw-waveform CSV CLI input.

### O6. Best-axis ideal pi-gate comparison — `examples/scope_rf_best_axis_xpi_heatmap.py`

- **Inputs:** live/current raw RF trace, fixed square-pulse voltage calibration, demodulation/window settings, optional intended-command CSV overlays, and error-grid settings.
- **Method:** propagate the nominal measured waveform; extract its transverse rotation-axis phase; construct one ideal equatorial pi gate about that axis; use that single target for the entire error grid.
- **Assumptions:** the desired operation is a pi rotation. One unknown constant transverse-axis phase may be removed. The target is not refitted at each error point, and angle errors or unwanted Z rotation remain visible.
- **Boundary:** this assesses a pi gate up to one fitted equatorial axis. It does not certify alignment to an independently calibrated laboratory X axis. Unlike O5, center fidelity need not be one.
- **Defaults/outputs:** the same common scope/carrier settings and 900 steps/101-by-101 grid; grid size must be odd. Overlay paths default to `None`. Produces a fixed-target heatmap and optional diagnostics; no raw CSV CLI option.

### Shared numerical and device modules

| Module | Inputs | Function and assumptions |
| --- | --- | --- |
| `rigol_dho.py` | VISA resource/session plus `WaveformCaptureConfig` | SCPI transport, preamble parsing, 1-based point/time conversion, chunked RAW/ASCII reads, trigger waits, CSV output. Live dependencies are imported when needed; tests can inject a fake resource manager. |
| `rf_demodulation.py` | Raw `ScopeWaveform`, carrier Hz or FFT-estimation request, cutoff Hz, filter order, Q sign | Mix to I/Q, low-pass, derive envelope/unwrapped phase, detect automatic or manual pulse bounds. The cutoff must be below Nyquist; defaults use a fourth-order Butterworth filter. Strongest non-DC FFT peak estimation is a convenience, not a carrier-validation measurement. |
| `pulse_robustness.py` | Demodulated trace/window, time-step count, fixed voltage scale or assigned area | Resample I/Q, construct controls and simulate a two-level Hamiltonian `H=((1+epsilon)*(Omega_x*sigma_x+Omega_y*sigma_y)+Delta*sigma_z)/2`. Fidelity is `abs(trace(U_target^dagger U))^2/4`. No relaxation/dephasing or independently measured spin populations are included. Standalone detuning is normalized to the model's mean envelope-derived Rabi rate. |
| `plotting.py` | `RobustnessResult`, `DemodulatedWaveform`, `PulseWindow`, `PulseModel` | Plot already calculated heatmaps, I/Q, envelope, phase, and controls; it does not acquire or calibrate data itself. |

## Redstone reusable projects

### R1. Waveform construction — `waveform.py`

Inputs are explicit mathematical parameters, not a scope trace. The outputs are numeric phase/amplitude columns, summaries, and reloadable configuration JSON. Phases are expressed in degrees; `phase_steps` quantizes one turn (base default 1024; several experiment notebooks select 65536). Amplitude values use the caller's requested scale; a generic 0–1 envelope is not automatically a physical voltage, Rabi frequency, or TNMR 0–100 percentage.

| Waveform | Required choices and interpretation |
| --- | --- |
| `Constant` | Point count and constant amplitude and/or phase. |
| `Sine`, `Triangle` | Point count, amplitude and/or phase output range, cycles, and phase offset. They generate numerical table shapes; the consuming sequence sets the time scale. |
| `Linear` | Point count and requested amplitude/phase ranges for a ramp. |
| `Chirp` | Point count, dwell in seconds, signed sweep width in Hz, sweep center, existing sequence frequency offset, and starting phase. Generates a phase table for a physical linear frequency sweep. |
| `HS1` | Chirp-like timing/frequency settings plus truncation and amplitude scale. Uses a sech envelope and a normalized tanh frequency sweep. |
| `SAHS1` | HS1 settings plus `nutation_hz`, the Rabi frequency corresponding to amplitude-table value one, and an amplitude ceiling. Adds a counterdiabatic quadrature and reduces the base HS1 field so the combined field fits the ceiling. Calibration of this amplitude unit is part of the input contract. |
| `WURST` | Timing/frequency settings, envelope order (default 20), amplitude scale. WURST envelope with a linear frequency sweep. |
| `WURSTtanh` | WURST settings plus tanh steepness `beta`; uses a tanh frequency sweep instead of a linear sweep. |
| `BB1` | Target angle and axis phase in degrees, split/correction-only choice, repeats, and duration representation. Its default `duration_units='subpulse'` gives a segment phase list; downstream code must supply the correct segment durations or expand them with the angle weights. A five-value list is not automatically a uniformly sampled BB1 waveform. |

For Chirp/HS1/WURST variants, the phase table is the **negative** time integral of requested physical frequency offset minus the sequence's existing offset. Redstone PhMod uses the opposite sign from the physical RF-frequency offset. `center_hz`/`offset_hz` must use the same frequency reference; the waveform object does not discover the TNMR carrier setting. Total sampled duration is `points * dwell_s`.

### R2. Offline TPS parsing/editing — `sequence.py`

- **Inputs:** a real TPS binary, raw TPS bytes, or a compatible `Sequence` JSON dump.
- **Capabilities:** inspect rows/events, parameter pages, parameters, table definitions and references; update existing parameters; place waveform values in existing tables; separately bind a table to a control-line/event slot; remove unreferenced table definitions; write TPS or JSON.
- **Assumptions:** names match the template exactly. `set_waveform_to_table()` requires an existing table; it does not assign that table to an event. Shared table edits require explicit `allow_shared=True`. `assign_table_to_event()` uses one-based visible event numbers. Parameters must already exist and retain their type/limits/read-only metadata.
- **Format boundary:** row/event decoding is partly inferred from observed TPS structures. Unknown chunks are retained as raw bytes. This is not proof that every vendor version or arbitrary edited sequence is semantically valid in TNMR.

### R3. TNMR COM automation — `tnmrcontrol.py`

- **Inputs:** Windows with registered TNMR COM server, optional program ID override (`TNMR_APPLICATION_PROGID`, default `NTNMR.Application`), an existing TNMR process or explicit launch request, and a valid document path or active document.
- **Capabilities:** connect/bind/open; query application and documents; list Dashboard parameter pages; get/set named parameters; get/set complete table contents; load/save a sequence; ZG/Go/Stop/Abort/Reset; save or Save As a document; produce a status snapshot.
- **Assumptions:** software-specific parameter and table names are valid for the selected document. Table values may be strings or iterable entries; iterable entries are formatted as CRLF-delimited text. Default `connect()` attaches without launching TNMR. Live COM work is serialized through one owner thread.
- **Testing input:** fake application/document objects can be injected. That permits software tests without TNMR and does not validate the installed COM server.

## Every Redstone example notebook

All paths in this section are under `hardware_capture/rf/redstone/examples/`. Defaults are inherited examples and may require replacement. Notebook code is authoritative where an older title or introduction is less precise.

### N1. `waveform_example.ipynb`

Generates a duration-weighted BB1 phase column and a separate sine-amplitude example. Inputs default to target 180 degrees, axis `-X`, 256 total phase samples, and 1024 phase quantization steps; the sine example uses 16 samples in the range 0–1. BB1 segment angles determine sample allocation. No experiment file or hardware connection is required. Outputs are table values/preview data; choose the desired phase/amplitude output settings.

### N2. `chirp_waveform_example.ipynb`

Generates a Chirp phase table and plots frequency, phase, and I/Q. Inputs default to 20,000 points, 0.2 microsecond dwell (4 ms total), signed sweep width -160 kHz, 65536 phase steps, and table/output name `chirp1`. The sequence-offset convention must match the eventual TNMR use. Writes a one-column text table; no TNT/TPS input or COM connection.

### N3. `write_waveform_json_example.ipynb`

Writes and reloads waveform configurations. The examples use a 5120-point Chirp, 5 kHz sweep, 5 microsecond dwell, 2500 Hz offset; and a 64-point Sine with amplitude 0–1 and phase 0–180 degrees. Writes `chirp_waveform.json` and a sine JSON with summary. Reloading reconstructs a waveform object, not a TNMR experiment.

### N4. `parse_sequence_to_json.ipynb`

## Closed-loop projects

### C1. Stage 1 phase-reference acquisition — `closed_loop_optimizer/run_stage1_calibration.py`

- **Inputs:** an existing TNT configured to consume amplitude and phase tables for the same RF event; actual scope connection and trigger setup; an independently known scope-voltage-to-Rabi scale; and the physical Rabi frequency at amplitude-table value 100.
- **Template contract:** default table names `ampmod_p180` and `phmod_p180`; 6000 entries over 60 microseconds (10 ns per entry); amplitude entries 0–100 and phase entries in degrees. The script does not create or validate all timing/event semantics of an arbitrary TNT.
- **Pulse contract:** generates split BB1 X(pi) with phases `0, phi, 3*phi, phi, 0`, `phi=acos(-1/4)`, and duration weights 1:2:4:2:1. RF amplitude is calculated to give total area 5*pi from the supplied calibration, assuming local linearity of TNMR amplitude.
- **Reference acquisition:** five captures by default. Estimate one constant phase from the stable first/last zero-phase segments, require end-segment agreement and repeatability, and check all BB1 segment residuals. Defaults allow 10 degrees first/last disagreement, 5 degrees capture spread, and 15 degrees maximum segment-pattern residual.
- **Important distinction:** this is a phase-reference project that consumes an existing amplitude calibration; it does not independently determine that amplitude calibration. The phase offset corrects the analysis frame and is not added to the uploaded TNMR phase table.
- **Window assumption:** when `PULSE_START_S=None`, detect once and freeze a 60 microsecond interval for subsequent captures. The pulse must remain in that interval and be correctly triggered.
- **Outputs:** independent final capture, phase-reference plots, commanded/measured pulse comparison, fixed-X(pi) heatmap, `stage1_summary.json`, and other run artifacts. It performs zero Adam updates by construction.
- **Default execution:** `DRY_RUN=True`; an exact live confirmation setting is also required for instrument operation.

### C2. Stage 1 plus iterative optimization — `closed_loop_optimizer/run_two_stage_optimizer.py`

Consumes the same instrument/template/calibration inputs as C1 and runs that phase reference first. It then repeats upload, arm, TNMR ZG, capture, demodulation, evaluation, and update. Default control representation uses 1500 amplitude and 1500 unwrapped-phase coefficients mapped by cubic B-splines to 6000 table entries.

The objective uses one fixed ideal X(pi) target in the calibrated analysis frame. Default error grid is 21-by-21 over +/-0.5 fractional amplitude and normalized detuning. Here detuning is normalized to the **independent amplitude-100 Rabi reference**, unlike the standalone heatmaps' mean-envelope reference. Objective weights combine mean fidelity (0.25), a smooth 0.99-threshold term (0.60), and a 95%-confidence lower-tail/CVaR term (0.15).

The GRAPE derivative with respect to measured I/Q is analytical. The mapping from uploaded controls to a future hardware capture uses an approximate identity Jacobian; no measured hardware transfer-function derivative is supplied. A locally useful response to small updates is therefore an experimental assumption. Current defaults request 100 updates, learning rates 0.02, amplitude-coefficient step cap 0.02, and phase-coefficient step cap 0.10 rad. Dry run remains enabled.

Outputs include capture/history/checkpoint data, initial/best/final controls, TNMR-ready tables, and heatmaps. Normal completion restores the best measured candidate. Error handling attempts TNMR stop and restoration of the original table contents; the source TNT is opened but not saved by the optimizer.

### C3. Synthetic optimizer demonstration — `closed_loop_optimizer/demo_stage2_offline.py`

No external files, scope, or TNMR are required. Inputs are built-in simulation constants: 40 coefficients per control, 160 waveform entries, 60 microseconds, a 125 kHz amplitude-100 reference, a 7-by-7 error grid from -0.25 to +0.25, and three updates. The synthetic measurement applies 0.82 amplitude scaling and a `0.14*sin(2*pi*position)` rad phase distortion. Prints objective/center/mean/worst fidelity and PASS only if all requested improvements occur. This tests a specific simulated distortion, not general hardware convergence.

### C4. Reusable optimizer engine — `closed_loop_optimizer/core.py` and `pipeline.py`

`core.py` consumes normalized I/Q arrays, per-entry durations, a physical Rabi reference, error grids, spline coefficients, and Adam state. It implements BB1 initialization, spline mapping, phase-reference estimation, fixed-target propagation/objective, GRAPE derivatives, coordinate-gradient conversion, and bounded Adam updates.

`pipeline.py` consumes `ClosedLoopConfig` plus real or injected fake TNMR/scope objects. It owns table formatting/readback, synchronized acquisition, demodulation/resampling, frozen phase reference, reporting, restoration, and connection cleanup. It is the common engine for C1 and C2; it is not a separate experiment definition.
